  <files>app/Support/YamlBlockEditor.php, tests/Unit/YamlBlockEditorTest.php</files>
  <behavior>
    Reusable helper that performs scoped-block replacement on YAML files. The public surface MUST be designed for Phase 25/26 reuse without speculative generality.

    Public API (planner-locked; the three subcommands in Tasks 2-4 consume this):
    - `public function __construct(string $filePath)` — bind to a single YAML file. No I/O until called.
    - `public function readBlock(string $key): mixed` — return the parsed value of the top-level key (e.g. `repos:`), or `null` if absent. Uses `Symfony\Component\Yaml\Yaml::parse()` on the extracted block text. For non-scalar blocks (lists, maps) returns the decoded array; for scalars returns the scalar value.
    - `public function writeBlock(string $key, mixed $value): void` — splice. Locate the existing `<key>:` block via regex (anchored to start-of-line at column 0; matches the block header + all subsequent indented or list-marker continuation lines until the next top-level key or EOF). Render the new block via `Yaml::dump([$key => $value], 4, 2)` and substitute. If the block does not exist, append it at the end of the file with one blank line separator.
    - `public function deleteBlock(string $key): void` — remove the block entirely (including its header line).

    **Line-ending policy (locked):** `YamlBlockEditor` PRESERVES the file's dominant line ending across read/write. Detect on read by counting `\r\n` vs `\n` occurrences; majority wins (ties → LF). Emit on write using the same ending throughout the rewritten file (the rendered block from `Yaml::dump()` always emits LF; the implementation MUST post-process it to match the detected dominant ending before splicing). A Windows-edited config stays CRLF; a Unix-edited config stays LF.

    Behavior MUST (Pest unit tests cover each — 10 tests, all first-class entries):

    1. **Test 1 (round-trip with no comments):** read a fixture with `repos: [...]` → assert parse → write back unchanged → file equals original byte-for-byte (modulo `Yaml::dump`'s canonical formatting of the rewritten block).

    2. **Test 2 (out-of-block comment preservation, byte-equivalent regions):** fixture content is the literal string `"# comment-A\n\nrepos:\n  - slug: a/b\n    path: /x\n\n# comment-B\n"`. Run `writeBlock('repos', [['slug' => 'c/d', 'path' => '/y']])`. Assert TWO substring guarantees on the resulting file:
       - `str_contains($result, "# comment-A\n\nrepos:")` — the blank-line glue between `# comment-A` and `repos:` survives.
       - `str_contains($result, "\n\n# comment-B\n")` — the blank-line glue and trailing newline after the block survive.
       Stronger assertion (also required): capture the pre-block region (everything before the first occurrence of `repos:` at column 0) and the post-block region (everything after the block's last continuation line) pre- and post-rewrite; both regions MUST be byte-equal. This pins the "byte-for-byte" CONTEXT.md promise harder than a line-presence check.

    3. **Test 3 (in-block comment loss is documented):** fixture with `repos:` + a `  # in-block comment` line between two entries → write a new repos value → assert the in-block comment is gone (this is the documented trade-off; the test pins the contract).

    4. **Test 4 (missing-block append):** fixture with NO `repos:` block at all → `writeBlock('repos', [...])` → file now ends with a blank line then the rendered `repos:` block + trailing newline.

    5. **Test 5 (block at start-of-file):** fixture where `repos:` is the very first line → write → no leading blank-line damage.

    6. **Test 6 (block at end-of-file without trailing newline):** fixture lacking trailing `\n` → write → file ends with exactly one `\n`.

    7. **Test 7 (CRLF line endings preserved):** two sub-assertions:
       - **7a:** fixture written with `\r\n` line endings throughout → `readBlock('repos')` parses successfully → `writeBlock('repos', ...)` → resulting file's dominant line ending is still `\r\n` (assert `substr_count($result, "\r\n") > substr_count($result, "\n") - substr_count($result, "\r\n")`, i.e. more `\r\n` than bare `\n`). Out-of-block comment `# comment-A\r\n` survives byte-for-byte.
       - **7b:** fixture written with `\n` line endings throughout → write → resulting file has ZERO `\r` bytes (`str_contains($result, "\r") === false`). LF-dominant stays LF.

    8. **Test 8 (deleteBlock):** fixture with `repos:` block → `deleteBlock('repos')` → block gone, file otherwise intact.

    9. **Test 9 (readBlock returns null when absent):** fixture with NO `repos:` key → `readBlock('repos')` returns null without throwing.

    10. **Test 10 (commented-out block ignored):** fixture with both a `# repos:` commented-out example AND a real top-level `repos:` block → `writeBlock('repos', [...])` mutates ONLY the real block; the `# repos:` comment line survives byte-for-byte. (This pins the start-of-line anchoring + comment-skip behavior of the block-extraction regex against the real-world GlobalConfig default YAML, which ships with commented examples.)

    Implementation notes (executor discretion):
    - Block-extraction regex must anchor to start-of-line (`^`/`(?m)`-aware) so it does not match `# repos:` (commented-out) or indented-under-parent `  repos:`.
    - "Block end" detection: next non-empty line at column 0 that is NOT a comment AND NOT a continuation of the current block. Continuation = leading whitespace OR `-` list-marker at column 0 (rare but valid for lists; though for `repos:` we always see indented children).
    - Constructor injection (per CLAUDE.md): `new YamlBlockEditor($path)`. No static state.
    - `RuntimeException` for I/O failures (per CLAUDE.md).
    - Explicit return types.
